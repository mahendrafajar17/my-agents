====================================
CONFIGURATION UPDATE PROCEDURE (v1.3.5 -> v1.4.0)
====================================
Tambahkan property berikut di config.yaml (bin/config.yaml):

1. mongodb.collection.call_mapping: call_mapping
   - Collection name untuk mapping call_id → sender_id
   - Digunakan saat event media_update_failed tanpa metadata

2. mongodb.collection.call_mapping_config: call_mapping_config
   - Collection name untuk konfigurasi TTL call_mapping
   - Default TTL: 24 jam (jika tidak ada di collection)

Full block yang perlu ditambahkan:
```
  collection:
    ...
    call_mapping: call_mapping
    call_mapping_config: call_mapping_config
```

FRESH INSTALLATION PROCEDURE
====================================
1. Setup MongoDB:
   - Create database: converter
   - Create collection: call_mapping, call_mapping_config

2. Insert initial config di call_mapping_config:
   db.call_mapping_config.insertOne({ ttl_hours: 24 })

3. Create TTL index (auto via EnsureIndexes saat startup):
   db.call_mapping.createIndex({ created_at: 1 }, { expireAfterSeconds: 86400 })

4. Setup RabbitMQ:
   - Declare exchange: cloud.converter-msgin.test (type: fanout)
   - Declare queue: cloud.converter-msgin.test
   - Bind queue to exchange

5. Copy config.yaml.example ke bin/config.yaml, sesuaikan host/port

6. Copy binary ke bin/

7. Start: ./bin/launch.sh

====================================
FEATURE CHANGES v1.4.0
====================================
1. WA Audio/Video Call Support
   - Handle webhook events: connect, terminate, media_update, media_update_failed
   - Routing via field "calls" → waCallPayload()
   - Audio call SDP: opus/48000 codec
   - Video call SDP: BUNDLE audio+video (opus + H264/90000)
   - include RTCP-FB NACK/PLI

2. OTP Authentication Webhook
   - Handle button payload: DID_NOT_REQUEST_CODE
   - Routing via field "messages" → convertMsgIn()
   - from_logical_id preserved

3. Model Changes
   - Contact: add UserID field, Profile → pointer (omitempty)
   - Messages: add FromLogicalID field
   - Change: add Errors field (change-level errors)
   - WaChange: add Errors field, Metadata → pointer (conditional)

4. call_mapping Collection (Media Update Failed Fallback)
   - connect event → save call_id → sender_id ke collection call_mapping
   - media_update_failed tanpa metadata → lookup senderID via call_mapping
   - TTL index on created_at, configurable via call_mapping_config (default 24h)
   - Unknown call_id → message skipped (no webhook)

5. E2E Integration Test (Testcontainers)
   - MongoDB 6.0 + RabbitMQ 3 via Docker testcontainers
   - 13 test cases: 12 call events + 1 edge case
   - make e2e, make e2e-run targets

====================================
TROUBLESHOOTING GUIDE
====================================
1. "Failed to ensure indexes"
   → Pastikan collection call_mapping ada. Buat manual jika perlu.

2. "SenderID not found, ignore queue" pada media_update_failed
   → call_mapping lookup gagal. Pastikan connect event tersimpan sebelum media_update_failed.

3. "WaitDelay expired before I/O complete" (E2E test only)
   → Known issue Go runtime + go run. Tidak mempengaruhi production.

4. MongoDB connection failed
   → Cek auth_source: admin, auth_mechanism: SCRAM-SHA-256

5. RabbitMQ consumer not created
   → Cek collection queue_routing: application = "msgin_converter"
